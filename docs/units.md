# Spectrum units and historical BUNIT repair

The PRIMARY spectrum generated by `generate_all_spectra.py` is in solar flux
units (SFU), with FITS `BUNIT` exactly **`'sfu'`**. One SFU is **10,000 Jy**
(`10^-22 W m^-2 Hz^-1`). This is a physical unit conversion, not an arbitrary
display scale. Legacy daily spectra labeled `BUNIT='jy'` already contain SFU
values. Repair their metadata without multiplying or dividing their spectra.

## Source chain and scope

The operator inspected the actual installation used by the live cron job:

1. `pz47@inti:/data1/users/pz47/lwasolarview/run_two_day_inti.sh` sources
   `use_lwa.sh` and runs `/data1/users/pz47/lwa-venv/bin/python`.
2. `generate_all_spectra.py::one_day_proc` invokes
   `suncasa.dspec.dspec.Dspec.read(..., source='lwa', ...)`.
3. That delegates to `suncasa.dspec.sources.lwa.read_data`. The inspected reader
   calibrates XX and YY with factors `cx` and `cy`, forms
   `I = 0.5 * XX / cx + 0.5 * YY / cy` (with background subtraction when used),
   and rebins time and frequency. Its final
   `transpose(...).reshape(...)/1e4` converts Jy to SFU exactly once for **all
   Stokes and all calibration paths**, including calibration-table, modified
   calibration-factor, and no-table paths.
4. The LWA branch of `Dspec.read` stores these values in `self.data` and sets
   `self.spec_unit='sfu'`. `Dspec.tofits` defaults its argument to `'jy'`, but
   when exporting `self.data` it writes the existing array with that argument
   as metadata; it does not perform a numeric conversion. Omitting the argument
   at the original/open/background export sites caused the metadata bug.

All three exports now explicitly pass `spec_unit='sfu'`. No spectrum arithmetic
was added. Both generator `Dspec.plot` calls also explicitly request SFU.
The inspected upstream plot API supports this argument and leaves numeric values
unchanged when `self.spec_unit` is already SFU. The standalone
`plot_spec_fits.py` now labels Stokes I and its `--vmax` argument in SFU;
V/I remains dimensionless. Existing daily/hourly PNGs and separately produced
synoptic plots are **not automatically regenerated** by a metadata migration.

Source references for review:
[Dspec read/export/plot implementation](https://github.com/suncasa/suncasa-src/blob/master/suncasa/dspec/dspec.py),
[LWA reader implementation](https://github.com/suncasa/suncasa-src/blob/master/suncasa/dspec/sources/lwa.py),
and [Dspec plot API](https://suncasa-src.readthedocs.io/en/latest/_modules/suncasa/dspec/dspec.html).
These upstream links can change; the supplied inspection of the deployed
installation establishes the live behavior. This change does not edit
site-packages, cron scripts, or deployment paths.

SFU describes **PRIMARY spectrum values only**. Raw input or calibration-table
quantities with Jy units, including background flux in Jy, retain those units;
calibration factors are separate quantities, not SFU spectra. Neither this
change nor the migration relabels HDF5 input, calibration tables, `FREQ_CAL`
columns, `TUNITn`, frequency/time extensions, or `DATASUM`. PRIMARY data bytes
are also untouched. The same final reader conversion applies to the known
historical daily products from **2023 through the present**, not just recent
dates. There is no migration date cutoff. Provenance must still be established
for each selected archive; a genuinely Jy-valued foreign spectrum must not be
relabelled as SFU.

## Historical migration

`tools/fix_spec_v2_bunit.py` uses only the Python standard library on POSIX
(including `fcntl.flock`). It requires an explicit directory and defaults to a
read-only dry run. Run these commands with the checkout and a **known original
LWA spec_v2 archive**, initially a disposable copy. The paths below are
placeholders; no production migration was performed while developing this fix.

```sh
python3 tools/fix_spec_v2_bunit.py /path/to/spec_v2/fits

# Use a new journal in an existing directory outside the selected data directory.
python3 tools/fix_spec_v2_bunit.py /path/to/spec_v2/fits \
  --apply --journal /path/to/migration-journals/sfu-20261004.jsonl

# Freshly reread exactly the files listed in that journal; never mutate them.
python3 tools/fix_spec_v2_bunit.py \
  --verify /path/to/migration-journals/sfu-20261004.jsonl
```

Only immediate entries with exact ASCII `YYYYMMDD.fits` names and valid calendar
dates are candidates. There is no recursion. Other names, including corrected
product suffixes and open/background product names, are excluded and counted as
`ignored`. A matching filename that is a symlink, directory, or multiply linked
file is rejected, not silently skipped. Directory and journal paths containing
symlinks are refused. Hard links are rejected to avoid modifying another name
outside the selected scope.

For each candidate, the tool scans complete 2880-byte PRIMARY header blocks to
`END`, even when BUNIT lies beyond the first block. It validates scalar cards,
structural order, END padding, unique value keywords, axis lengths, floating
point image format, payload extent, and whole-file block alignment. The header
safety limit is 16 MiB. It also checks the historical writer signature:
`FILENAME`, `ORIGIN='NJIT'`, `OBJ_ID='SUN'`, `TYPE=1`, `BTYPE='flx'`,
`BNAME='Flux Density'`, `POLARIZA='I'`, `EXTEND=T`, a four-axis image with
singleton baseline axis and one or two Stokes, daily observation dates, and
LWA-range frequencies in GHz (0.010–0.100). Telescope must be LWA, OVRO-LWA, or
the writer's historical default EOVSA. The filename/signature checks reduce
accidental selection of foreign products; they cannot prove raw-data origin
for a foreign file with identical metadata. Unusual historical formats are
rejected for review rather than automatically broadened to other products.

The tool rejects:

- Missing/duplicate BUNIT, incompatible units, malformed or truncated headers
  or payload extents, unsupported structure/scaling, and foreign signatures.
- Any PRIMARY `PBCOR` or `TDBCOR` card, even if false, because corrected products
  require separate provenance and handling.
- PRIMARY `CHECKSUM`, because changing its header would require recomputation.
  Extension checksums are unaffected by a PRIMARY-only edit. `DATASUM` is
  unchanged because no data bytes change.

Supported BUNIT values are `jy` and `sfu` with capitalization variants.
Jy variants and safely representable SFU variants become exactly lowercase
`sfu`; an existing lowercase `sfu` is idempotent. String padding is FITS padding,
not part of the logical value. The tool replaces **one existing 80-byte BUNIT
card in place**, preserving its comment where safely representable. It never
adds a card, serializes an HDU, alters image values, or rewrites extensions.

Every run prints counts for candidates, processed/ignored entries, potential
changes, completed changes, unchanged/verified files, rejections, errors, and
unprocessed candidates. Dry run and verify report individual failures and keep
checking the remaining files. Apply/rollback stop at the first rejection or
error, retain the journal and summary, and return a nonzero exit status. Earlier
successful changes remain recorded; this is not an archive-wide transaction.

## Durability, verification, and limitations

Per-file nonblocking shared locks protect read-only inspection; exclusive locks
protect apply and rollback. Files are opened without following symlinks and
checked against their directory entries. Before writing, the tool stores a
`prepare` record with the absolute path, file/directory device and inode,
file size/timestamps, header size, card offset, **exact original and replacement
80-byte cards as hex**, a digest of the primary header outside that card, and
deterministic payload sample offsets/lengths/SHA-256 digests. The new journal is
created exclusively with mode 0600; existing journals are never overwritten or
appended to. Its creation and records are fsynced before any FITS write.

After journaling, the tool freshly rereads the primary header/card and samples
and checks unchanged inode, size, mtime, and ctime before the write. It writes
only the target card, fsyncs the FITS, rereads the header and card, compares
primary-header bytes outside the card with the pre-write header, checks the
file/directory identities and size, and compares the payload samples. A durable
`complete` record follows successful verification. Journal-path identity is
also checked while recording changes.

The samples cover up to five deterministic 4096-byte windows at the start,
quarter points, and end of **all bytes after the primary header**, including
extensions and padding. This is explicitly **sample verification, not a full
payload checksum**. Unit tests compare the entire payload of small generated
fixtures; those tests are not a raw-data comparison of production spectra.
`--verify` reads precisely the journal's prepared paths under fresh locks and
checks their replacement cards, file/directory identities, size, primary
header outside the card, and those same samples. It does not require the old
mtime/ctime, which legitimately changed during migration. Files moved,
replaced, resized, or subsequently regenerated need review.
Unchanged files produce no `prepare` records. An apply run with no changes
therefore leaves an empty journal; `--verify` rejects an empty journal rather
than claiming that any files were checked. `changed` counts completed,
verified writes; after a write/verification error, a pending preparation may
represent an unchanged, partially written, or corrected card and must be
inspected with the retained journal.

Locks are advisory. The live generator may not honor them, so arrange a quiet
maintenance window for application and rollback. Timestamp/identity checks
detect many concurrent modifications but do not make a noncooperating writer
safe. Unsampled payload changes cannot be ruled out. An in-place 80-byte write
is not guaranteed atomic across power loss or I/O failure; the durable original
card and partial-run journal are essential recovery information. Maintain
normal archive backups separately; the journal backs up the card, not spectra.
Extension contents are not parsed or validated, only sampled and left alone.

## Rollback and interrupted runs

Rollback defaults to a read-only preview, rereads the recorded files, and
requires the exact replacement card, identity, size, unchanged primary-header
remainder, and payload samples before restoring the original card.

```sh
python3 tools/fix_spec_v2_bunit.py \
  --rollback /path/to/migration-journals/sfu-20261004.jsonl

python3 tools/fix_spec_v2_bunit.py \
  --rollback /path/to/migration-journals/sfu-20261004.jsonl \
  --apply --journal /path/to/migration-journals/rollback-20261004.jsonl

# The rollback journal's replacement is the exact original card (possibly Jy).
python3 tools/fix_spec_v2_bunit.py \
  --verify /path/to/migration-journals/rollback-20261004.jsonl
```

The rollback journal itself backs up the corrected card before restoring the
old card, using the same safeguards and verification. An original mixed-case
unit and its spacing/comment are restored byte for byte. Repeating migration
is idempotent; repeating an already completed rollback is rejected because its
expected corrected card is gone.

After interruption, preserve the journal and run `--verify`. Each `prepare`
record is checked even without a `complete` record: this handles a fully written
card whose completion record was interrupted. If the file still has its
original card, verification fails rather than claiming success; rerunning
migration with a **new** journal handles remaining original files and skips
already corrected files. Keep every journal for later rollback.

For a torn/partial BUNIT write, the guarded rollback refuses an unexpected
card. For an incomplete JSONL tail, the journal reader refuses to guess.
Preserve the original journal and inspect a copy to recover complete `prepare`
records. They contain `path`, `device`, `inode`, `size`, `header_size`,
`card_offset`, `original_card_hex` and verification digests. An operator can
restore exactly `bytes.fromhex(original_card_hex)` at `card_offset` after
independently validating file identity, unchanged surrounding header and data,
locking the file and arranging exclusive access; fsync and reread afterward.
Never restore by filename alone, overwrite the whole header, or rescale values.
Automatic partial-write recovery is deliberately not implemented.

## Recorded validation

Tests require only Python's standard library and generated temporary FITS byte
fixtures; they do not import suncasa, astropy, or numpy or read production files.

```sh
python3 -m unittest discover -s tests -v
python3 -m py_compile generate_all_spectra.py plot_spec_fits.py \
  tools/fix_spec_v2_bunit.py tests/test_sfu_units.py
git diff --check
```

The initial RED run, before implementation, ran 13 tests and reported 15 failures
(subtests included), covering the missing CLI and metadata regressions. Its
output was recorded at `/tmp/lwasolarview-sfu-red.log` during development.
The expanded suite additionally covers durable backup ordering, locks,
concurrent writes/replacements, sync/short-write failures, and interrupted
journal verification. Generator AST tests check all three explicit export
arguments and execute the export expressions with unchanged numeric fixtures.
The final run passed **25 tests**; `py_compile` and `git diff --check` passed.
No real raw-data comparison, deployment, migration, commit, or push is claimed.
